# Аудит и доработка v3 — 21 октября 2026

Сохранён существующий проект Python 3.12 + PySide6 Essentials 6.12 + Telethon 1.45.0 + SQLite, фоновый поток с asyncio. Интерфейс расширен двумя вкладками. Библиотека использует TL layer 229; schedule_repeat_period присутствует в отправке, редактировании и серверном Message. Официальная документация повторно проверена: https://core.telegram.org/api/scheduled-messages, https://core.telegram.org/method/messages.sendMessage, https://core.telegram.org/method/messages.editMessage.

| Функция | Состояние v2 / проблема | Изменение v3 |
|---|---|---|
| API-реквизиты | API ID и Hash повторно задавались по профилям | Одна защищённая пара для приложения; миграция прежних реквизитов, отдельная вкладка |
| Сессии | Независимые, подключение кнопкой | Автовосстановление сохранённой сессии без автоматического запроса кода |
| Контроль аккаунта | Перед созданием/массовым изменением | Дополнительно перед чтением групп/очередей, привязкой и очисткой прогресса |
| Повторы | Реальный серверный параметр 86400, сверка ответа | Сохранены; проверяется также форматирование |
| Интервалы | Замкнутый цикл, фиксированный запас 60 | Запас по умолчанию 60, явная настройка ≥60; тесты 90/46/23 слотов |
| Синхронизация | getScheduledHistory и уникальное сопоставление | Автоматическая сверка известных групп после подключения, обработка событий изменения очереди |
| Доставка | Отдельной статистики не было | Сохраняются только доказанные sent_messages из серверных событий, с дедупликацией; неизвестные итоги явно обозначены |
| Диагностика | Только общий статус связи | Сдвиг от исходного цикла, отсутствующие/дополнительные/изменённые записи, конфликт интервала, уменьшение запаса |
| Шаблоны | Только обычный текст, без версий | Явный Telegram HTML, предпросмотр, версии и подтверждённое восстановление |
| Массовая правка | Текст и повтор | Текст, сущности форматирования и повтор; изменения только оформления тоже учитываются |
| Удаление аккаунта | Скрытие с восстановлением | Дополнительно явное необратимое стирание файлов удалённого профиля |
| Хранение | SQLite v2 | Транзакционная миграция v3 с резервной копией, сохранением random_id и незавершённых операций |
| Ошибки | Общие технические сообщения | Понятные сообщения для основных ошибок входа, прав, Premium и лимита очереди |
| Проверки | 47 тестов | 60 автоматических тестов, дополнительно протокол реального двухдневного теста |

## Изменённые файлы

app.py — общие настройки, автовход и синхронизация, HTML/версии, диагностика и удаление локальных данных.
engine.py — единая API-конфигурация, проверка аккаунта, события Telegram, форматирование, диагностика, явный запас.
profiles.py — ограниченное удаление файлов только выбранного отключённого профиля.
storage.py — backup и миграция v3, сохранение сущностей форматирования и незавершённых правок.
planner.py — параметр запаса с прежним значением по умолчанию.
synchronization.py — учёт форматирования при сопоставлении.
application_settings.py (новый) — защищённые общие реквизиты, миграция и история шаблонов.
formatting.py (новый) — разбор Telegram HTML, сериализация и проверка сущностей.
diagnostics.py (новый) — анализ смещений и конфликтов без изменения очереди.
tests/test_v2.py, tests/test_gui.py, tests/test_v3.py, tests/render_ui.py — проверки и макеты интерфейса.
package_release.py, README.md, GUIDE_V3.md, AUDIT.md, VALIDATION.md, REAL_TELEGRAM_TEST.md, validation-results.json, screenshots/ — упаковка и результаты.

## Сохранность данных

До изменения кода создан архив backups/source-before-v3-*.zip. При первом открытии существующей базы приложение создаёт progress.sqlite3.before-v3-*.bak через SQLite backup, затем выполняет транзакционную миграцию. Прежние сессии, шаблоны, планы и random_id сохраняются. Глобальные реквизиты переносятся в защищённый файл application/api.dpapi; исходные настройки и DPAPI-файлы остаются для отката. В архивах релиза пользовательских данных нет.

## Ограничения и критерий готовности

Реальное взаимодействие с аккаунтом и два суточных цикла пока НЕ проверены. Работоспособность на конкретном Telegram-аккаунте нельзя объявлять окончательно подтверждённой до выполнения REAL_TELEGRAM_TEST.md. Нет QR-входа, медиа, альбомов, каналов и групп-форумов. HTML ограничен возможностями установленного парсера Telethon; произвольный HTML/CSS не поддерживается. Большие сдвиги/неоднозначность требуют ручной привязки. Пропуски не вычисляются по отсутствию сообщения. Счётчик отправок покрывает только полученные серверные события, не весь период отключения. Windows 10 и другой компьютер отдельно не проверены; цифровой подписи нет.
