# Реальный двухдневный тест Telegram — НЕ ВЫПОЛНЕН разработчиком

Проводить только после явного согласия пользователя, на собственном тестовом чате с разрешением публикаций. Не использовать рабочие группы для первого теста. API Hash, код, 2FA и session-файлы в отчёт не включать.

## Перед началом

1. Распаковать весь архив v3, запустить EXE. Сохранить API ID/API Hash во вкладке 8, войти локально с Premium-аккаунтом. Проверить, что указан нужный аккаунт и Premium.
2. Оставить тестовый режим включённым. Выбрать один тестовый чат, записать его ID, правило и slow mode. Проверить отсутствие чужих отложек. Сохранить согласованный интервал, запас 60 секунд и часовой пояс.
3. Создать уникальный тестовый шаблон, например «Тест ежедневного сотрудничества — дата проверки», выбрать HTML и добавить жирное слово. Сделать предпросмотр. Зафиксировать ожидаемый текст и оформление.

## День 1: создание и закрытое приложение

4. Установить первый слот через 10–15 минут, режим ежедневный, предел 1. Построить и проверить план, затем явно подтвердить создание. В журнале должен быть подтверждён период 86400. Любая ошибка — остановка теста и проверка очереди, без повторной отправки вслепую.
5. В официальном Telegram открыть отложенные сообщения этого чата. Сверить дату, текст, оформление и ежедневный повтор. Записать время и ID из приложения, при необходимости сделать собственный скриншот.
6. Закрыть приложение полностью. Дождаться первого слота. В официальном Telegram зафиксировать фактическое время публикации и появление следующей отложки. Не считать отсутствие сообщения доказанным пропуском без дополнительной проверки.
7. Через небольшой интервал открыть приложение. Проверить автоматическое восстановление аккаунта без нового кода, очередь, новый ID, период 86400 и диагностику смещения. При неоднозначности не нажимать массовое обновление, выполнить явную привязку после сверки.
8. Изменить текст и только оформление в шаблоне. Сохранить, показать массовый предпросмотр и подтвердить одну правку. Сверить в официальном Telegram новый текст, оформление, прежнюю дату и ежедневный повтор. Немедленной публикации быть не должно.

## День 2: второй цикл

9. Снова закрыть приложение. После времени второго слота проверить публикацию обновлённого текста и очередную отложку на третий день. Записать фактические времена двух отправок и периоды повторов.
10. Открыть приложение и синхронизировать. Проверить соответствие нового ID, смещение от исходного цикла, независимость от локального процесса. Счётчик полученных событий может быть меньше фактических отправок, если программа была закрыта; это ожидаемо и явно подписано.

## Отдельная проверка Slow Mode

11. В собственной группе с обычными участниками проверить выбранным аккаунтом реальное применение Slow Mode: администратор может быть освобождён от ограничения. Записать роль тестового аккаунта. Получить кулдаун через приложение, сравнить с настройками официального Telegram.
12. Если разрешено ещё одно тестовое сообщение, создать его отдельной подтверждённой операцией в тестовом режиме. До создания убедиться, что план учитывает первый занятый слот и границу суток. Для кулдауна 15 минут использовать минимум 16 минут; для 30 — 31; для 60 — 61. Не провоцировать FLOOD_WAIT массовыми запросами: его обработка проверена mock-тестами.
13. При смещениях проверить, что диагностика показывает сокращение запаса или конфликт. Приложение не должно автоматически переставлять сообщения. Увеличение запаса — только явный выбор для нового плана.

## Второй аккаунт и завершение

14. Добавить второй доступный аккаунт: вводятся номер, код и при необходимости 2FA; повторный ввод API ID/API Hash не нужен. Проверить отдельные группы/шаблоны/планы. Вернуться на первый профиль и убедиться, что его данные сохранены.
15. В первом профиле явно выбрать тестовые отложки и подтвердить удаление. Проверить пустую тестовую очередь в официальном Telegram. Удаление профиля из программы само по себе не останавливает серверные повторы.

## Ручная проверка кастомных эмодзи v3.5 — ещё НЕ выполнена
На собственном тестовом чате после явного подтверждения: импортировать один и несколько разных анимированных эмодзи со смешанным форматированием; создать один тестовый ежедневный слот; проверить анимацию, текст и повтор в официальном Telegram; повторить на втором аккаунте с нужными правами/Premium. Проверить фактический следующий ежедневный цикл, повторный импорт и подтверждённое массовое редактирование. Проверить отказ аккаунта без нужных прав без замены эмодзи обычным текстом. Автоматические проверки имитируют сервер и суточный переход; они не доказывают фактическое воспроизведение анимации или доставку после суток на сервере Telegram.
v3.7: отдельно проверить на собственном тестовом чате после подтверждения: редактирование текста вокруг двух кастомных эмодзи; перенос одного слота с сохранением повтора; сдвиг нескольких слотов; отмена длинной операции и сверка реально изменённой части. Эти живые проверки ещё не выполнены.
v3.8: живую проверку следует выполнять только на указанном пользователем собственном тестовом чате после его явного разрешения. Запрошено подтверждение одного тестового слота, редактирования, переноса и удаления; до получения ответа операции Telegram не выполнялись. Уведомления Windows также требуют визуальной проверки на компьютере пользователя с разрешёнными уведомлениями.

## Живая проверка 10.11.2026 — выполнена
Через указанный пользователем профиль проверен указанный личный диалог Telegram. Создана ровно одна тестовая отложка примерно на 20 часов вперёд. Сервер подтвердил schedule_repeat_period=86400. Текст изменён и перечитан; время перенесено на 10 минут вперёд с сохранением повтора. Тестовая запись удалена через DeleteScheduledMessagesRequest, последующее чтение подтвердило пустую очередь. До теста очередь также была пустой. Обычных сообщений в переписку не отправлялось. Сохранённые сессии и настройки пользователя не менялись; прогресс теста записан отдельно.
Это проверка серверных операций создания, редактирования, переноса и удаления. Фактическая доставка через сутки, анимация кастомных эмодзи, права групп и массовое заполнение в этой живой проверке не тестировались. Готовые архивы и EXE версии 3.8 не изменялись.
