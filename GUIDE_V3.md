# Telegram Offer Scheduler v3 — руководство

Приложение для размещения вашего предложения о сотрудничестве в группах, где это разрешено. Банковских офферов и материалов РКО в комплекте нет. OpenAI API, ChatGPT и сервер не нужны.

## Запуск и обновление

Распакуйте весь архив Windows в отдельную папку. Запустите TelegramOfferScheduler.exe. Папку _internal рядом с ним сохраняйте. Установленный Python не требуется. Приложение не подписано цифровой подписью.

Пользовательские данные находятся в прежнем каталоге приложения, отдельно от EXE. Старый профиль сохраняется. Перед обновлением схемы SQLite автоматически создаётся файл progress.sqlite3.before-v3-*.bak. Архив исходников до доработки находится в backups рабочего проекта. Не заменяйте пользовательские файлы файлами из чужих профилей.

## Аккаунты и настройки

На вкладке 8 «Общие настройки» один раз введите API ID/API Hash и сохраните. На вкладке аккаунта добавьте профиль, введите номер телефона, затем код Telegram и при необходимости пароль 2FA в локальном окне. При добавлении следующего аккаунта повторный ввод API ID/API Hash не требуется. Секреты в переписку не нужны.

Общие API-реквизиты хранятся в application/api.dpapi. При обновлении берётся первая доступная прежняя пара, начиная с активного профиля. Прежние настройки и защищённые файлы остаются для отката. Новые сессии и API Hash защищены Windows DPAPI для текущего пользователя Windows. Старый файл account.session сохраняется для совместимости: он остаётся чувствительным файлом, не передавайте его. DPAPI-файлы нельзя просто перенести под другого пользователя Windows.

Каждый профиль имеет отдельные настройки, шаблоны, очередь операций и базу прогресса. Один Telegram-аккаунт нельзя повторно подключить как независимый профиль. Переключение во время операции недоступно. Удаление профиля убирает его из списка, сохраняя файлы; предусмотрено восстановление. Оно не отзывает сессию Telegram и не удаляет серверные отложки. Кнопка «Стереть данные» позволяет отдельно, с необратимым подтверждением, удалить локальные файлы ранее удалённого профиля. Общие API-реквизиты и данные остальных профилей сохраняются.

Настройте общую паузу запросов и отдельную паузу первоначального создания (1–60 секунд). Это ограничение скорости, а не обещание отсутствия FLOOD_WAIT. Выберите часовой пояс отображения. Изменение пояса не меняет момент публикации.

## Первая проверка

Тестовый режим включён по умолчанию. Он ограничивает изменяющую операцию одним сообщением в одном чате, но это реальная операция Telegram после подтверждения, а не симуляция.

Подключите аккаунт, загрузите чаты и выберите собственный тестовый чат. Создайте шаблон сотрудничества, назначьте его чату, укажите разрешение администратора и согласованный интервал. Постройте предпросмотр, проверьте текст и время и подтвердите создание. Обновите серверную очередь и проверьте ежедневный повтор. После проверки удалите тестовую отложку через приложение. Для рабочих групп отключайте тестовый режим только после проверки.

Разработчик не выполнял авторизацию или публикации на вашем аккаунте. Автоматические тесты используют отдельные временные файлы и mock-клиент.

## Расписание

Интервал равен max(15 минут, slowmode Telegram, вручную заданный разрешённый интервал) + запас, по умолчанию ровно 60 секунд. Его можно увеличить вручную в настройках аккаунта; минимум 60 секунд. Старые расписания при изменении запаса автоматически не меняются. Поле примечания необязательно и не участвует в проверках или отправке.

При свободной очереди и интервале 16 минут получается 90 слотов. Проверяется также расстояние между последним и первым слотами суточного цикла. Занятые слоты и ограничения очереди уменьшают доступное количество. Новые слоты создаются последовательно по ближайшему времени между выбранными чатами.

Ежедневный режим передаёт schedule_repeat_period=86400. Проверяются наличие поля в библиотеке, Premium и фактическая очередь после запроса. При недоступности функция выдаёт ошибку, а не подменяет её локальным повтором. Обычное однократное расписание — отдельный явный выбор пользователя.

После подтверждённого создания повторениями управляет Telegram, программу можно закрыть. Telegram рассчитывает следующий повтор от фактической отправки; задержки сервера могут сдвигать время. Программа не может гарантировать неизменность серверных правил или точное время отправки.

## Шаблоны и массовое изменение

Создайте несколько шаблонов и назначьте нужный в строке каждого чата. Отредактируйте шаблон, сохраните его, выберите чаты и откройте предпросмотр обновления связанных сообщений. Проверьте старый/новый текст, затем подтвердите применение.

После редактирования приложение повторно читает серверную очередь и проверяет текст, дату и повтор. Ошибка одного чата отображается отдельно; остальные чаты могут продолжить обработку. Незавершённые изменения сохраняются: откройте их предпросмотр и повторно подтвердите.

После ежедневной отправки идентификатор отложки может измениться. Синхронизация сопоставляет текст, период и фазу суточного расписания с допуском 120 секунд. Сопоставление допускается только при единственном кандидате с обеих сторон. При неоднозначности, внешнем изменении или большем сдвиге автоматическое изменение блокируется. Обновите список и явно привяжите выбранное серверное сообщение к шаблону. Скрытых меток в тексте нет.

На вкладке очереди также доступны редактирование выбранных сообщений, удаление и включение/выключение ежедневного повторения с подтверждением. Изменение повторения проверяется повторным чтением Telegram.

## Прерывание и продолжение

Отмена останавливает дальнейшую работу, но не откатывает уже подтверждённые изменения. FLOOD_WAIT/SLOWMODE_WAIT сохраняются и соблюдаются; ожидание можно прервать. Повтор создания использует сохранённый random_id. Неизвестный результат сетевого запроса сначала сверяется с сервером. Новая сессия программы не сбрасывает сохранённое ожидание.

Если очередь или текст вручную изменены в Telegram, повторно загрузите её и разрешите конфликт явно. Не удаляйте базу прогресса ради ускорения повторной отправки.

## Ограничения

Поддерживаются текстовые офферы в обычных группах и супергруппах. Каналы и группы-форумы исключены из списка. Медиа и альбомы не реализованы. Нет обхода блокировок и автоматического получения разрешений администратора.

Проверены Windows 11, mock-сценарии и локальный запуск EXE. Windows 10, реальная авторизация и полный суточный цикл Telegram в этой среде не проверены. Факт установки повтора на конкретном аккаунте подтверждается только ответом Telegram во время вашей тестовой операции.

Официальные источники: https://core.telegram.org/api/scheduled-messages и https://core.telegram.org/method/messages.editMessage.


## Новое в версии 3

При запуске и переключении приложение пытается подключить сохранённую сессию, проверяет идентичность аккаунта и Premium, загружает группы и синхронизирует ранее сохранённые группы. Автоматического запроса нового кода нет: если сессия истекла, введите телефон и нажмите вход. Сетевой сбой не удаляет сессию. Никаких автоматических отправок при подключении нет.

У каждого шаблона собственный формат: обычный текст либо Telegram HTML. Старые шаблоны сохраняют обычный текст, поэтому знаки < и > не превращаются внезапно в разметку. Поддерживаются базовые HTML-сущности клиента: жирный, курсив, подчёркивание, зачёркивание, код, блок кода, ссылка. Используйте «Предпросмотр текста». Markdown не реализован. Произвольные веб-страницы, CSS и изображения не поддерживаются.

Изменения только форматирования тоже попадают в массовый предпросмотр. Программа отправляет и проверяет сущности Telegram вместе с текстом и повтором. Предпросмотр массовых изменений показывает текст и его HTML-представление. Проверка после редактирования консервативная: если сервер нормализует формат иначе, операция может потребовать ручной проверки.

История версий сохраняется при сохранении настроек/шаблона и закрытии. Одинаковые версии не дублируются. «История версий / восстановить» позволяет выбрать, посмотреть и подтвердить возврат локального текста/формата. Это не редактирует Telegram до отдельного массового применения.

Во вкладке 7 «Диагностика» доступны исходный слот, текущий ID, смещение по фазе суточного цикла, отсутствующие/изменённые и дополнительные сообщения, уменьшение запаса и конфликты разрешённого интервала. Для контроля границы суток очередь анализируется циклически; разовые сообщения при таком анализе учитываются консервативно как занятые фазы. Список включает фактические даты во вкладке очереди. Диагностика не исправляет время автоматически.

Во время подключения обрабатываются updateNewScheduledMessage и updateDeleteScheduledMessages. При наличии sent_messages сохраняется подтверждённая связь отложенного и отправленного ID; одинаковое событие не увеличивает счётчик повторно. Это счётчик полученных событий за время наблюдений, не полный итог за период отключения программы. Пропуски и отправки без доказательства остаются «не подтверждено». Отсутствие отложки не считается доставкой или пропуском.

Для полного реального теста следуйте REAL_TELEGRAM_TEST.md. Обновление схемы v2→v3 сохраняет прежние записи и незавершённые операции; до изменения выполняется SQLite backup. Используйте отдельную папку для новой сборки и не запускайте старую версию на базе v3.


## Ярлык на рабочем столе (v3.1)

После распаковки в постоянную папку откройте вкладку 8 «Общие настройки» и нажмите «Создать ярлык на рабочем столе». Ярлык запускает эту копию программы с текущей папкой данных. Учитывается перенаправленный рабочий стол, в том числе OneDrive. Повторное нажатие обновляет совпадающий ярлык; чужой ярлык с тем же названием не перезаписывается. После переноса папки программы создайте ярлык заново.


## Поиск групп и участники (v3.2)

На вкладке 2 введите часть названия чата в поле поиска. Регистр букв не важен, крестик очищает поиск. Фильтр не снимает ранее установленные галочки: над таблицей указано количество выбранных групп, скрытых поиском. Перед массовой операцией проверьте весь выбор. Колонка «Участников» находится рядом с названием; число обновляется при загрузке групп. Если Telegram не предоставляет данные, отображается «Недоступно», а не ноль. Для получения отсутствующего числа приложение запрашивает сведения о группе последовательно с установленными паузами.


## Заполнение всей очереди после теста (v3.3)

Если создался только один слот, проверьте тестовый режим и предел очереди. Во вкладке 4 нажмите «Заполнить очередь на 24 часа — показать полный план». Кнопка отключает тестовое ограничение, выбирает ежедневный повтор, предел общей очереди 100 и начало не ранее чем через 10 минут. Она только готовит предпросмотр, не создаёт сообщения. В плане проверьте число существующих и новых отложек, затем нажмите «Подтвердить создание плана». При 16 минутах и одном существующем ежедневном слоте можно добавить 89 при достаточном временном окне и доступном лимите Telegram. Старое сообщение не удаляется. Используйте тот же шаблон и прежнюю папку данных. Если слот не сопоставился после повторения, сначала обновите очередь и подтвердите привязку. Незавершённый план продолжается кнопкой «Продолжить сохранённый план».


## Ограничение зависших запросов (v3.4)

Отдельный сетевой запрос, подключение и шаг входа ограничены 40 секундами. Это не ограничивает длительность всего заполнения очереди. Кнопка остановки проверяется также во время ожидания сетевого ответа. В статусе отображается текущий запрос; длительные паузы показывают оставшееся время каждые 30 секунд. FLOOD_WAIT/SLOWMODE_WAIT сохраняются и соблюдаются; после трёх последовательных отказов одного запроса операция прекращается с сохранённым временем ожидания. При тайм-ауте отправка могла выполниться на сервере: продолжение сначала сверяет очередь, неопределённый результат не отправляется повторно вслепую. Если отмена низкоуровневого запроса не завершилась, дальнейшие запросы блокируются до перезапуска. Перед повторным действием обновите очередь.

## Импорт из «Избранного» (v3.5)
1. В Telegram отправьте готовый текст с кастомными эмодзи и форматированием в «Избранное».
2. Подключите этот аккаунт в программе. Вкладка 3 → «Импортировать из Telegram» → выберите сообщение → задайте имя шаблона. Показываются текстовые сообщения среди последних 100, без фото/видео/файлов. Для более старого текста отправьте его заново в «Избранное».
3. Проверьте текст и счётчик кастомных эмодзи. Отдельного проигрывателя анимации в программе нет.
4. При необходимости нажмите «Копировать в другой аккаунт», выберите профиль. Сессии, очередь и настройки второго профиля не переносятся и не изменяются.
5. Назначьте шаблон разрешённым группам; подготовьте полный план или один тестовый слот и подтвердите создание обычным способом.
6. Для изменения текста отредактируйте исходное сообщение в Telegram и повторите импорт под тем же именем. Для существующей очереди отдельно выполните предпросмотр обновления связанных сообщений и подтвердите изменения. Локальный импорт сам ничего не публикует.
7. История версий сохраняет исходные entities. После перезапуска шаблон доступен без повторного импорта.

Весь текст импортированного шаблона защищён от правок, чтобы не сдвинуть UTF-16 границы эмодзи. Для обычного редактируемого текста создайте новый шаблон. Права на использование Premium-эмодзи проверяет сервер на аккаунте отправителя; копирование шаблона не предоставляет Premium. Импорт по ссылке не реализован: используется выбор из «Избранного».

## v3.6 — редактирование и удаление установленной очереди
Вкладка 5 «Очередь Telegram»: выберите группы на вкладке 2, обновите очередь, выделите строки (Ctrl/Shift для нескольких).
- «Редактировать сообщение…» или двойной щелчок: изменение текста одного обычного сообщения с предварительно заполненным исходным текстом. Дата и повтор сохраняются, локальный шаблон не изменяется.
- «Заменить выделенные шаблоном…»: явный выбор сохранённого шаблона, просмотр нового текста и подтверждение. Подходит для одного или нескольких сообщений, включая кастомные эмодзи. Сообщения с форматированием редактируются этим способом: нужный новый шаблон подготовьте/импортируйте на вкладке 3.
- «Удалить выделенные отложенные…»: подтверждённое удаление одного или нескольких сообщений из серверной очереди вместе с их будущими повторами. Уже опубликованные сообщения остаются. Удалённые связанные слоты не восстанавливаются командой продолжения старого плана.
После успешной операции список автоматически перечитывается с сервера. Если запрос завершился ошибкой или отменой, обновите очередь вручную перед повторным действием. Изменения внешним клиентом проверяются перед записью; работа со вложениями ограничена удалением. Тестовый режим по-прежнему ограничивает действие одним сообщением: для массовой операции отключите его во вкладке расписания.

## v3.7 — управление очередью, прогресс и резервные копии
1. Вверху окна — число подтверждённых сообщений, текущий чат и этап, прошедшее время и примерная оценка остатка. Пауза между запросами и ограничения Telegram отображаются отдельно с отсчётом. Оценка приблизительная и зависит от ответов сервера. При загрузке/проверке без известного числа изменений индикатор показывает активность.
2. В группах — текущий итог создания «подтверждено X из Y», ошибки и результаты проверки. Двойной щелчок по статусу открывает полный текст. После чтения очереди статус группы показывает текущую очередь и число связей; подробности предыдущей операции остаются в журнале.
3. Вкладка 5: поиск по группе, тексту, названию шаблона, ID; фильтры «Все», «Ежедневные», «Разовые», «Требуют проверки». Последний включает незавершённые изменения, ошибки и сообщения без локальной связи. Статус виден в отдельном столбце и подсказке. При скрытии строки её выделение снимается; массовые операции действуют только на видимые выделенные строки.
4. «Редактировать сообщение…» теперь позволяет менять текст вокруг кастомных эмодзи и внутри форматированных фрагментов. Позиции entities пересчитываются в UTF-16. Удаление/замена кастомного эмодзи и неоднозначное пересечение границ форматирования блокируются с объяснением. Для другого набора эмодзи или сложного переоформления импортируйте новый шаблон. Это текстовый редактор, а не проигрыватель анимации.
5. «Перенести время…»: для одного сообщения — выбор даты и времени в часовом поясе расписания, для нескольких — общий сдвиг в минутах. Проверяются ближайшие 24 часа, slow mode, ручной интервал, последняя публикация и переход через полночь. Сначала предпросмотр, потом отдельное подтверждение. При подтверждении серверное состояние проверяется заново. При сдвиге вперёд сначала перемещаются поздние слоты; назад — ранние. Перенос, требующий временно нарушить интервал, отклоняется, даже если конечный план выглядел бы допустимым. Текст, entities и повтор сохраняются. Вложения не редактируются.
6. Массовая замена/удаление и перенос показывают полный список «было → станет» в прокручиваемом окне. Нет обрезания до первых 12 сообщений. Изменения выполняются последовательно, поэтому отмена или ошибка могут оставить уже подтверждённую часть применённой; обновите очередь. При неизвестном результате переноса используйте предпросмотр незавершённых изменений: сохранённая операция сверяется по ID и старой/новой дате, а не отправляется вслепую.
7. Вкладка 8: «Создать резервную копию…» и «Восстановить…» для текущего профиля. При первом открытии существующих настроек в v3.7 автоматически создаётся копия before-v3.7; перед восстановлением — отдельная before-restore. Копируются шаблоны, entities, история версий, группы и настройки интервалов. Сессии, пароли, API-реквизиты и очередь Telegram в эти копии не входят. Для другого аккаунта сначала переключите профиль. Копии находятся в подпапке backups папки данных профиля.

Реальная отправка, анимация и доставка спустя сутки в Telegram в этой доработке не проверялись. Тесты используют временные профили и имитацию Telegram; список живых проверок находится в REAL_TELEGRAM_TEST.md. Работа приложения не использует OpenAI API.

## v3.8 — аккаунты, часы, чередование, проверка и установка
1. Вкладка 9 «Все аккаунты»: локальный обзор всех активных профилей — число сохранённых групп, отложки по последнему снимку очереди, незавершённые/ошибочные действия, ближайшая дата по снимку и время проверки. Это НЕ live-мониторинг всех аккаунтов. Если дата уже прошла, показано предупреждение. Для свежих данных переключитесь на профиль и обновите его очередь на вкладке 5.
2. Вкладка 2 → выделите галочками группы → «Часы публикации и чередование…». Часы фиксированы по Москве (UTC+3), независимо от часового пояса отображения расписания. Начало включается, конец исключается; одинаковое время означает круглосуточно. Поддерживаются ночные окна, например 22:00–02:00. Настройка относится к НОВОМУ плану; уже созданные повторяющиеся сообщения сами не меняются. Для них используйте перенос/удаление. При продолжении сохранённого плана проверяются новые разрешённые часы; неподходящий слот останавливается.
3. В том же окне перечислите названия шаблонов по одному на строку в порядке чередования. Пустой список — единственный шаблон из таблицы групп. Текст, entities, template_id каждого слота фиксируются в базе; закрытие программы не нарушает план. Каждый созданный слот повторяет назначенный ему оффер ежедневно; это не фоновая смена текста одного сообщения. Полный предпросмотр показывает шаблон и текст каждого слота.
4. Вкладка 4 → «Проверить готовность без создания сообщений»: проверка членства/прав на текст, подтверждения разрешения, Premium для повтора, доступности очереди, slow mode, интервалов, часов, конфликта локального плана и числа доступных слотов под выбранный предел. Сводка в поле предпросмотра. Проверка не создаёт план для исполнения и не отправляет сообщения. Точный серверный лимит очереди и доступность каждого Premium-эмодзи невозможно гарантировать такой проверкой; окончательное решение остаётся за Telegram. После проверки отдельно подготовьте и подтвердите план. Права могут измениться позднее.
5. Вкладка 8 — переключатель уведомлений Windows. Программа уведомляет о завершении/ошибке и вынужденном ожидании Telegram. Уведомления работают только пока приложение открыто и Windows разрешает системные уведомления; фокусировка внимания может их скрывать. После закрытия приложения серверные повторы продолжаются, но локальных уведомлений нет.
6. Вкладка 9 → «Экспорт отчёта текущего аккаунта»: CSV (UTF-8, разделитель точка с запятой), журнал известных программе созданий, изменений, удалений и ошибок. Даты по Москве. Это не полная история доставок за время отключения программы. Текст включён в отчёт; сессии и API Hash не экспортируются.
7. TelegramOfferScheduler-3.8-Setup.exe — мастер установки без прав администратора. Закройте старое приложение, запустите установщик, выберите базовую папку и установите. По умолчанию: LocalAppData/Programs/TelegramOfferScheduler/3.8. Старые версии остаются на месте; существующие данные из LocalAppData/TelegramOfferScheduler используются новым приложением. Ярлык приложения обновляется, его прежний --data-dir сохраняется. Перед первым открытием существующих настроек создаётся резервная копия before-v3.8. Повторная установка поверх той же папки 3.8 запрещена: запустите уже установленную копию либо выберите другую базовую папку. Для обновления будущей версией используйте её новый установщик; автоматической загрузки обновлений из интернета нет. Для переносного запуска остаётся ZIP-архив.

Сборка установщика из исходников: сначала собрать приложение и выполнить package_release.py; скопировать Windows ZIP как payload.zip рядом с Installer.spec; выполнить python -m PyInstaller --noconfirm Installer.spec. Итоговый Setup.exe появится в dist. Инсталлятор хранит приложение в отдельной версии и не удаляет старые установки или пользовательские данные.

## v3.9 — исправление автопроверки и порядка очереди
В 3.8 после загрузки списка групп автоматически запускалось чтение очередей всех сохранённых групп, независимо от галочек. Для 235 групп это сотни последовательных запросов GetScheduledHistory/GetFullChannel, при этом счётчик оставался 0/?. В 3.9 этот автозапуск удалён полностью: обновление списка заканчивается после загрузки списка. Для чтения отложек отметьте нужные группы и нажмите «Обновить очередь выбранных групп» на вкладке 5.

Проверка очередей показывает название текущей группы и конечный счётчик обработанных групп; ошибки также учитываются, повторяющиеся ID групп проверяются один раз. Пустой список не отправляет запросов. Остановка прерывает проверку перед следующей группой. Тайм-аут и ограничения Telegram сохранены.

Таблица отложек отсортирована по ближайшей дате, затем по чату и ID. Заголовок «ID Telegram» поясняет, что это серверный идентификатор, а не номер позиции в расписании. Непоследовательные ID не перенумеровываются: редактирование/удаление использует настоящий ID выбранной строки. Изменение сортировки не меняет сообщения, время, повтор или локальные связи.

Установка: закройте 3.8 и запустите TelegramOfferScheduler-3.9-Setup.exe. Если старая версия занята обходом групп, нажмите «Остановить операцию», дождитесь остановки и закройте окно. Нажатие остановки не удаляет существующие отложки.

## v4.0 — очистка групп, каналов и чатов

1. Переключитесь на нужный профиль на вкладке 1 и подключите аккаунт.
2. Откройте вкладку 10 и нажмите «Загрузить / обновить все чаты аккаунта». Список читается без изменений Telegram.
3. Используйте поиск, тип, папку и сортировку. Дата — время верхнего сообщения, которое Telegram вернул в списке диалогов. Для личных чатов число участников не показывается.
4. Мышью, протяжкой или Ctrl/Shift выделите диапазон и нажмите «Отметить выделенные». Можно также ставить галочки по одной или отметить все видимые. Отметки хранятся отдельно от видимого выделения строк.
5. Перед очисткой программа покажет весь список. После подтверждения каждый диалог обрабатывается отдельно. Ошибка одного диалога не снимает отметки с него; успешные строки удаляются из списка.

Кнопка «Остановить операцию» проверяется между диалогами и во время сетевого ожидания. Уже выполненные Telegram действия не восстанавливаются. Перед повтором всегда обновите список.
